# 05｜Notion正文、研究记录和安全发布

## NOT-01｜先读目标并保护旧稿
先读取目标、相关子页、地图及当前连接器的Notion Markdown规范。用户未授权覆盖时保留原页、建候选；明确覆盖时先创建可恢复的完整快照并回读核验，再修改。保留原生子页/数据库标签、旧版引用及有用内容；工具提示子内容可能删除时停止排查，不自行绕过保护。原课程只读，私有材料不进入公开仓库。

## NOT-02｜先研究记录，后教学正文
先建立并核验关联Research Record，保存来源、Claims、矩阵、解释素材、分层设计和写作前案例评分；随后写正文并持续补充测试/评估/发布事实。未写、未测、未读不能提前标通过。研究页链接正文，正文提供研究入口；矩阵、版本SHA和完整日志留在研究页。

## NOT-03｜推荐正文的教学功能
标题在页面属性，正文不重复H1。按主题组织而非强制小节数：
1. 具体工作/学习问题、前置知识、可验证学习目标及模拟性质。
2. 朴素尝试与不足，一次早期完整体验。
3. 按依赖展开核心机制：输入、中间变化、结果、为什么如此。
4. 取舍与反例、必要的关系/状态示意，适量主动推演。
5. 分层实践与验证、真实实现桥梁、适用和失败条件。
6. 延伸内容/后续入口，末尾Review Recap与迁移自测。
主体为连贯段落，少分段；来源紧邻重要主张。不要把执行过程说明放在学习问题前面占据开篇。

## NOT-04｜发布后检查结构与细节
回读主要标题、代码完整性/语言、表格列与内容、链接/提及、全部子页标签、版本与最终状态。需要时比较保存代码与实际运行代码。额外检查转义的粗体标记、裸星号、意外链接的文件名、泄漏的HTML/Markdown及长行可读性。发现明确格式错误先修复；无法判断显示的项标待视觉复核，不能以“块存在”宣称显示正确。可用且适合时做浏览器视觉检查；未做则明确只完成API结构/内容检查。回读前不报发布完成；异步写入必须等结果，警告必须处理。

## NOT-05｜回执与历史分明
更新研究页当前状态为draft_only/created_new/updated_existing/blocked，并保留有时间/阶段标记的历史状态，避免顶部“待发布”和尾部“已完成”混淆。回执给真实目标、快照、研究记录地址、完成范围及未验证项；输出四项独立评估与主要学习体验修复。用户要求逐项执行检查时，附各条款ID及用户额外要求的映射，不把未验证项算完成。
