# 07｜首次学习者模拟审查、深度解释与回归检查

说明：这是编辑模拟，不代表真实用户实验。默认读者有 Python 基础，但正在第一次系统学习这个 Agent 主题。**请在阅读时主动扮演完全不知晓该技术的学习者，而不是审阅概念是否“说得没错”。**

## 第一次读者七问（v0.3）

1. **为什么要学？** 阅读开头能否理解具体工作问题、原先简单方案的缺口？不先出现十个术语。
2. **为什么不是直接使用朴素方法？** 是否具体演示至少一个失败/边界情况，读者可以看见“错在哪里”？假想输出要标明是示意。
3. **究竟怎么运作？** 是否跟得上输入、重要中间步骤、判断/反馈、输出？一处跳过核心步骤、只给定义则 `revise`。
4. **这个名词和相邻名词有什么区别？** 首次出现是否先用自然中文说用途，再给 English；有必要的反例与限定，比喻不是误导。
5. **案例选得合适吗？** 默认是否通用、高频、真实可感？是否避免将用户职业、健康、宗教或其他个人背景机械地当作贯穿例子？用户明确指定的场景除外。
6. **怎样证明它有用？** 若改进了策略，是否说明新增的措施解决哪个缺点，如何控制变量测试？没有真实 LLM A/B 是否被明确标为“设计演化，未实测”？
7. **脱离笔记能解释吗？** 能否自己给出一个不同的工作例子，画出横向链并说明何时不用该方案；是否有最小实践和少量复习题？

## 不同 Step 使用不同的回归标准

**不能把 Step 2 的“工具请求→执行→反馈”强加到所有章节。** 按主题选择合适的过程：

- Prompt Engineering：模糊任务→明确规则→必要的 Few-shot→输出结构→验证；必须区分提示层与程序权限，Zero/Few-shot 与微调不同。
- LLM 基础：真实文本→Token/向量→模型机制→下一个 Token→解码输出；训练/推理与模型局限分明，不要求模拟器冒充真实 Transformer。
- Agent 核心：目标→模型决定→工具请求→程序执行→结果反馈→改变下一动作→停止；不同状态有不同分支。
- RAG：文档建索引与在线问答两条路径；召回与排序/重排序/生成分工；检索命中不意味着回答正确。
- Context/Memory：来源、选取、组织、压缩、持久化、注入权限；当前上下文不等于模型训练，也不必等于长期记忆。
- Tools/MCP：Schema、请求/执行、权限、失败与恢复；模型对外部动作的文字不等于真实执行。
- Planning/多 Agent：计划、依赖、反馈、失败/停止，何时固定 Workflow 更简单。

## 一份可操作的读者测试脚本

读完任一核心小节，合上笔记，用普通中文回答：

- “原来最简单的做法是什么，具体哪里不够？”
- “这个技术在中间具体做了哪两三件事？”
- “给一个输入，走完整条链，应该得到什么输出？什么地方可能失败？”
- “如果我要做一个最小 demo，怎样判断这一步真的发生了？”
- “它与相邻 Step 的方法有什么不同？”

若答案必须照抄定义才讲得出来，重新补写具体过程/例子；不要只在总结里再加几行定义。`reader_review=pass` 只表示编辑模拟无明显缺口，不是真实学习者效果证明。

## 保留的 Step 2 回归基准

订单查询案例：已发货后查询物流，未发货不应查询；工具结果影响下轮决策；Tool Calling 是模型请求，实际执行由应用处理；ReAct 与 Agent Loop 不等同，停止与错误分支存在，State/Trajectory 不等于长期 Memory。mock 只证明控制流，不是 LLM 能力实测。
