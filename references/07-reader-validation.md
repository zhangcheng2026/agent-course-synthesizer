# 07｜首次学习者模拟审查与回归检查

本审查只是编辑模拟，不声称有真实学习者参加。受众默认有 Python 基础但首次系统学习某个 Agent 主题。

1. **首屏直觉**：文章开头能否迅速看到核心问题、结论和实例？如果案例在大量概念之后，重排。
2. **术语前置**：每个新术语首次出现时是否已经解释用途？若需要同时理解四个新的概念，分步介绍。
3. **案例闭环**：至少呈现输入、决策、工具请求、真实执行、观察、分支和停止；不同观察应使下一步改变。
4. **冗余控制**：每个概念只保留一个主讲位置，重复的定义、图示、案例合并。
5. **边界控制**：完整 Queue/Worker/Checkpoint/长期记忆等内容转到后续 Step，正文只写与当前主题相关的必要部分。
6. **学习验收**：离开笔记能否画横向流程、解释 Tool Call 与工具执行、对比 Workflow/Agent、完成最小练习？代码性质、环境、预期、实际运行状态必须清楚。

报告 reader_review=pass/revise/blocked，并注明具体失败点和修法。若证据错误回到研究层，若知识正确却读不懂则回到教学重构，不要继续往主文添加审计材料。

## Step 2 回归基准

订单查询案例：已发货后查询物流、未发货不查询；工具结果驱动下一次决定；Tool Calling 是请求、执行由应用处理。描述 ReAct 与 Loop 不同，停止/错误分支存在，State/Trajectory 不等于长期 Memory。mock 只能证明程序控制流，不代表真实 LLM 能力。
