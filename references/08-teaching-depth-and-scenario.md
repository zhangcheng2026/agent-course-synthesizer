# 08｜按主题选择原课案例，不固定场景

## CASE-01｜选择优先级与跨课变化
先遵循用户明确指定的场景；否则先考察八门课已读选节的原例，再考虑必要改编/跨课综合，原例不适配时才自拟。适配优先于出处数量、办公场景偏好或新颖程度。可用课程中的旅行、天气、代码调试、检索、客服等例子，只要有真实读取依据且先备负担合适；不得声称某课有尚未读到的例子。不必每次都用开会，也不禁止合适的会议例。
不同Step可使用不同例子；同一Step复用主案例有助于连贯则保留。不要为多样性强行换题或堆八门课八个例子。可查看已完成Step的案例，记录本次复用/更换理由；每次重整同一Step也不必换例。用户职业背景不自动成为案例领域。

## CASE-02｜写作前评分与来源记录
至少评估拟采用案例；有合理备选时作简短比较，不为凑数量虚构备选。每项0–2分：0不符合、1需改编/补足、2符合；记具体理由和来源范围。安全准确/核心机制一致性有问题须修复后使用，不能靠总分放行。评分为编辑选择依据，不是实测教学效果。
| 维度 | 判断标准 |
| --- | --- |
| 可理解性/普遍性 | 读者已具备背景，或只需极少补充；不限定必须办公 |
| 问题具体 | 有输入、任务、约束和可检查输出 |
| 暴露问题 | 能合理展现朴素方法的缺口，不捏造模型实测 |
| 机制适配 | 能沿本主题关键因果展开，不把循环套在所有主题 |
| 可验证 | 有可观察变化、对照或判断标准 |
| 安全准确 | 来源/模拟身份清楚，改编未破坏业务和权限逻辑 |
评分前后记录example_id、出处、usage、改动、保留机制、未读/省略细节、预期教学作用和相邻Step案例关系；字段参见01。

## CASE-03｜引用、改编与综合的边界
原例准确转述并在相应位置标课程及小节；必要短引遵守适用版权限制，不整段搬运作为“综合”。替换人物、数据、环境或工具时标“改编自…”，解释会影响机制/结论的改变；无影响的改名无需在正文反复说明。综合不同例子须分别列来源及拼接部分；未实测的新结果标教学预期，不继承原作者的实验数字。原课强绑定框架时可保留任务/机制并做框架无关改编，但不能把接口改写后仍称原代码。

## CASE-04｜一条主线，必要对照
用主案例贯穿问题、早期体验、机制、验证；辅助例只为澄清主案例无法清楚表达的区别。后文复用要承担新教学功能，不重述全场景。核心与实践范围不匹配时可缩小实践并给真实桥梁，不能为避免另一个例子把教学扭曲。

## CASE-05｜写后检查六问与一致性
对重要概念检验：为何产生、朴素方法不足、是什么、怎样工作、新增能力与代价、怎样知道做对；不是机械六标题。核对输入/角色/日期/约束/中间状态/输出，模型输出不当事实，成功标签不越过实现。语言通俗、比喻有限定、深度与复习分开、模拟和实测分清。案例改变后重新检查受影响的逻辑与测试。
