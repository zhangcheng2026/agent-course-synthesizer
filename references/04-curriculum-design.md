# 04｜课程设计与知识依赖

## 从学习结果反向设计

1. 定义本节最低达标能力：**能解释、能画流程、能区分方案、能实现最小案例、能评价结果**。
2. 从这些能力倒推必须掌握的前置知识（如 RAG 需要 LLM 上下文、文档切分、Embedding、检索器，不要求先学完整 LangGraph）。
3. 建立有向无环的概念依赖：概念→机制→取舍→实践→验证；允许“先直观、后深化”，但不能在未定义术语前大量使用缩写。
4. 压缩重复论述时保留能解释因果的关键例子；删除话题无关的课程宣传和长篇套话。

## 五项教学检查

- `concept_map`：有无总框架和清晰概念关系？
- `prerequisite_map`：每个模块使用的前置知识是否已解释？
- `coherence`：章节是否连续、有无跳跃与循环引用？
- `threshold_concepts`：找出需要跨过的理解门槛（例如“检索质量和生成质量是两个不同问题”）。
- `backward_design`：每节配一个能检验学习目标的任务。

## 适合 AI Agent 的默认章节顺序

1. 为什么需要／解决什么问题、适用边界
2. 最小工作机制（给出横向步骤图）
3. 关键概念与组件
4. 进阶方案、技术权衡、失败场景
5. 与其他 Agent 组件关系（Tools／Memory／Context／MCP）
6. 最小可运行实践（如来源有代码，注明版本；否则给伪代码并标注）
7. 评估、常见误区、复习检查

> 这是默认框架，不是强行填充模板。若来源不包含具体实现，不得编造“来源中的实践”来填空；可标为“自拟练习”。
