# 02｜跨课程主题综合（Research Synthesis 核心）

## 工作法

1. 统一“概念名称”和“等价术语”，但**不消除关键差别**，如检索召回率 recall@k 与 top-k 命中率 hit@k 并非相同指标。
2. 以“解释什么问题”为中心对 claims 聚类。RAG 示例：问题与边界／文档建库／检索方法／上下文组织与生成／评估／Agentic RAG／安全。
3. 为每个 cluster 写一句可检验的 `theme_statement`，而不是抽象标签；列出支持、限制和差异。
4. 每个主题输出 `so_what`（为什么重要）与 `next_step`（实践中怎么验证），以学习应用而非商业决策为主。

## 六种关系标签

- `SAME`：同概念且限定条件一致，合并表述、保留全部来源。
- `COMPLEMENTARY`：不同部分互补，合并为连续解释、保留各自独到内容。
- `CONFLICT`：实质相反，列双方、技术/时间/定义背景与待验证证据。
- `UNIQUE`：单一来源的重要独有知识，仍需保留。
- `EVOLVED`：历史版本或技术演进，标记日期和 API 版本。
- `UNCERTAIN`：证据不足、原文歧义、数值无法核查；禁止写作确定事实。

## 输出矩阵

| 概念 | 综合结论 | 主张 IDs | 关系 | 来源数（去相关后） | 待核查项 | 建议放入课程位置 |
|---|---|---|---|---:|---|---|
| 例如：文本切分 | 小块更容易定位，但可能缺失上下文；结构切分、语义切分需权衡 | RAG-01、RAG-08 | COMPLEMENTARY | 2 | 默认块大小不通用 | 核心架构→分块 |

### 特别注意

- 不因大多数来源都说“RAG 减少幻觉”就写成“RAG 保证事实正确”。
- 识别“理论定义”和“某门课程实现方式”的区别；框架绑定代码不得变成概念定义。
- 用一条贯通的教学主线整合独有技术，而非按老师逐一重述。
- 对无法直接消解的争议，课程正文中呈现对比或限制条件，并在审计附录保留全文定位。
