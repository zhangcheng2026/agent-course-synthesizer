# 06｜质量审查与 Notion 发布协议

## 两轮审查

**第一轮：证据审查（必须过关）**：A. 所有核心知识可追溯；B. 报告来源覆盖率和未读章节；C. 来源转载不算独立支持；D. 有实质争议时显式保留；E. 技术版本、适用条件和评估指标不混淆；F. 未从草稿、示例输出中推导出实际实验结果。

**第二轮：教学审查**：学习目标可检查、章节依赖合理、无大段重复、关键机制和工程权衡保留、最小案例能帮助理解、复习问题覆盖重点。

## 量表（人工/模型辅助，须说明不是实测质量保证）

| 指标 | 分值 |
|---|---:|
| 原文准确与忠实度 | 25 |
| 已选范围覆盖完整性 | 20 |
| 跨课程综合质量 | 20 |
| 课程逻辑与教学结构 | 15 |
| 来源可追溯性 | 10 |
| 表达与复习体验 | 10 |

90–100：可发布；80–89：修改后再审；<80：重做。**硬性拦截优先于总分：**发现核心无来源结论、隐瞒冲突、未读却声称全量、错误指标、覆盖/覆写非目标内容，发布状态必须为 `blocked`。

## Notion 发布协议（对应第七阶段）

1. 使用 `notion-research-documentation` 读取、比对多来源；可结合 `notion-knowledge-capture` 沉淀验证记录。先确认目标页面和层级。
2. 发布模式缺省 `draft`：只返回审稿文本；用户已明确要求保存测试稿时，优先在目标课程根页创建**独立测试页**，保留既有 Step。
3. **更新已有 Step 必须有用户明确的该页更新请求**；修改前完整读取旧内容并确认版本。若未获准更新，则不能清空或覆盖。
4. 使用 Notion 写操作前读官方 Notion-flavored Markdown 规范；页面标题使用 page properties 而不是正文重复写标题。
5. 写后重新 fetch 新页/更新页，确认标题、段落、来源、质量说明和链接实际存在；若发生不可确认故障先搜索避免重复创建。
6. 返回验证后的 Notion URL 和发布状态；若未写入或受限，说清原因。
7. 以用户私有 Notion 页面为证据时，公开 GitHub 仓库仅放抽象知识、出处链接与示例说明，不大段复制用户原文或私有数据。
